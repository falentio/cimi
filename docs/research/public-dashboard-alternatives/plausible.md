# Plausible Analytics: Public and Shared Dashboard Access

**For:** Cimi issue [#8](https://github.com/falentio/cimi/issues/8), "Define public dashboard disclosure and access"

**Research date:** 2026-08-23

**Scope:** Public and shared dashboard links, and the data a recipient can read through those links. This report covers the public-link/token model, authentication, data scope, filters and time ranges, exports, indexing, revocation, rate limits, caching, and privacy controls. It does not evaluate Plausible's visitor-collection design except where that determines what a dashboard can disclose.

**Primary-source boundary:** The citations below are limited to Plausible-owned documentation, the official [`plausible/analytics`](https://github.com/plausible/analytics) repository, and Plausible's official privacy/data-policy pages. Documentation was checked on the research date. Source observations are pinned to master commit [`9cc669b97ece3ecd37fcb3950791cb3873d7944d`](https://github.com/plausible/analytics/commit/9cc669b97ece3ecd37fcb3950791cb3873d7944d), dated 2026-08-19. Plausible Cloud and Community Edition can differ; repository observations describe that source snapshot.

## Executive Findings

- **Fact (public dashboard):** A site is private by default. Enabling public visibility makes the site's dashboard available to anyone who has the site's dashboard link; disabling it makes the dashboard private again ([official visibility docs](https://plausible.io/docs/visibility), [site schema](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible/site.ex)).
- **Fact (shared dashboard):** A shared link grants access to one specific site's dashboard without a Plausible account or login. A shared link can optionally require a password and can be fixed to a site segment ([official shared-link docs](https://plausible.io/docs/shared-links)).
- **Fact (data access):** The recipient gets the interactive dashboard's aggregate analytics, not a raw event export through the dashboard. Plausible documents dashboard reports covering traffic, sources, pages, locations, devices, goals, properties, and other configured features; its repository README distinguishes these aggregated dashboard stats from raw data available to a self-hosting operator ([dashboard overview](https://plausible.io/docs/guided-tour), [metrics definitions](https://plausible.io/docs/metrics-definitions), [official README](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/README.md)).
- **Fact (export):** A shared-link viewer can use the dashboard export route. The official test suite exercises a CSV ZIP export through a shared link, and the export documentation says the quick export follows the selected date range and filters ([official export docs](https://plausible.io/docs/export-stats), [shared-link export test](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/test/plausible_web/controllers/api/stats_controller/dashboard_csv_export_test.exs)).
- **Inference for Cimi:** An unprotected shared link is a bearer capability: forwarding the URL forwards access. A public dashboard is broader still because it has no per-link secret at all. Neither mechanism is recipient-specific authentication or an Organization membership boundary.
- **Important gap:** Plausible documents segment scoping, but I found no official public/shared-dashboard control for a per-link expiry, viewer identity/audit, export disablement, per-link date-range cap, anonymous-link rate limit, or cache invalidation guarantee. Those gaps are listed explicitly below rather than treated as implied behavior.

### Public dashboard: tokenless site flag

- **Fact (source):** The site schema has a `public` boolean. `make_public/1` and `make_private/1` only change that boolean; the normal dashboard route is authorized with the `:public` role when `site.public` is true ([site schema](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible/site.ex), [site authorization](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/plugs/authorize_site_access.ex), [router](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/router.ex)).
- **Fact (docs):** Plausible describes this as making stats public to anyone with the stats dashboard link, and says the site is private by default ([visibility docs](https://plausible.io/docs/visibility)).
- **Inference for Cimi:** Public visibility is site-wide disclosure, not a separate dashboard object or a recipient-scoped capability. A public URL can be shared without having to protect or rotate a secret.

### Shared dashboard: per-site slug

- **Fact (source):** Creating a shared link generates a `Nanoid` slug, stores the slug on a `shared_links` row tied to a site, and builds a URL containing `auth=<slug>` ([shared-link creation and URL](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible/sites.ex), [shared-link schema](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible/site/shared_link.ex)).
- **Fact (docs):** Plausible describes a shared link as secure and impossible to guess by default, but does not describe it as an account-bound credential ([feature overview](https://plausible.io/docs/your-plausible-experience)).
- **Fact (source):** The shared-link controller requires the slug to exist for the requested site domain. A slug from another site does not authorize that other site ([shared-link lookup](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/controllers/stats_controller.ex), [site authorization and shared-link binding](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/plugs/authorize_site_access.ex)).
- **Fact (docs):** Recipients do not need a Plausible account or login and cannot see other sites in the owner's account ([shared-link docs](https://plausible.io/docs/shared-links)).
- **Inference for Cimi:** The slug functions as a bearer identifier for one Site. It should be handled as a secret even though Plausible calls it a shared link, because the documented access model does not identify or authenticate the recipient.

### Password protection

- **Fact (docs):** Password protection is optional. The password is set when the shared link is created; the documented UI does not let the owner see, edit, or remove it later. If it is forgotten, Plausible instructs the owner to delete the link and create a new one ([shared-link docs](https://plausible.io/docs/shared-links)).
- **Fact (source):** The password is stored as `password_hash`, not as the virtual plaintext `password` field ([shared-link schema](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible/site/shared_link.ex)).
- **Fact (source):** After a successful password challenge, the controller sets a cookie named from the slug containing a signed shared-link token. Later requests verify the cookie token and require its embedded slug to match the database row ([password flow](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/controllers/stats_controller.ex)).
- **Source discrepancy:** The controller comment says the password cookie permits access for 24 hours, but the token verifier passes `max_age: @one_hour_in_seconds * 24` while `@one_hour_in_seconds` is defined as `30 * 60`. That source expression is 43,200 seconds, or 12 hours, not 24 hours ([controller comment and cookie flow](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/controllers/stats_controller.ex), [token verifier](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible/auth/token.ex)). The browser cookie call also does not set an explicit cookie `max_age`; the signed token's verifier is the documented source-level expiry check.
- **Fact (docs):** Password-protected shared links cannot be embedded in an iframe; an unprotected link is required for the documented embed flow ([embed dashboard docs](https://plausible.io/docs/embed-dashboard)).

## Data Scope and Controls

### Site and data boundary

- **Fact (docs):** A shared link exposes the specific dashboard that was shared and no other sites in the account ([shared-link docs](https://plausible.io/docs/shared-links)).
- **Fact (source):** The shared-link route loads the site associated with the slug and renders the same `stats.html` dashboard used for dashboard access. Its internal stats routes are under `AuthorizeSiteAccess`, which treats a valid shared link as the `:public` site role ([shared-link rendering](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/controllers/stats_controller.ex), [router](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/router.ex), [authorization plug](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/plugs/authorize_site_access.ex)).
- **Fact (docs/source):** The normal dashboard exposes aggregate metrics and dimensions such as visitors, visits, pageviews, sources, pages, locations, devices, goals, conversions, and custom properties, depending on site configuration and plan ([dashboard overview](https://plausible.io/docs/guided-tour), [metrics definitions](https://plausible.io/docs/metrics-definitions), [Stats API dimensions and metrics](https://plausible.io/docs/stats-api)).
- **Fact (official README):** Plausible Cloud's dashboard view is aggregate-only; the README separately says self-hosting gives an operator access to raw data directly from ClickHouse. This does not make raw ClickHouse data available through a public/shared dashboard URL ([official README](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/README.md)).
- **Inference for Cimi:** Sharing a Plausible dashboard should be treated as disclosure of every aggregate report and dimension that the recipient can query through that dashboard, not as disclosure of only the headline chart.

### Segment limits

- **Fact (docs):** A shared link can be fixed to a saved site segment. Viewers cannot remove the base segment, can see the included filters, and can add filters on top. If they try to add a filter outside the base segment, Plausible says the result will contain no data ([shared-link segment docs](https://plausible.io/docs/shared-links), [filter and segment docs](https://plausible.io/docs/filters-segments)).
- **Fact (docs/source):** Only site segments can be selected for this shared-link restriction. In the source, a limited link is rendered with `limited_to_segment_id`, and the internal stats controller rejects requests whose first filter is not the required segment filter ([shared-link docs](https://plausible.io/docs/shared-links), [shared-link render and required-filter check](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/controllers/api/stats_controller.ex)).
- **Fact (source):** The shared-link settings form exposes password and segment selection on creation, but the edit form exposes name and segment controls, not a password field ([shared-link settings form](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/live/shared_link_settings/form.ex)).
- **Inference for Cimi:** Segment scoping is a server-side disclosure boundary, but it is not a static report snapshot. A recipient can still explore within the allowed segment and export its filtered aggregate data.

### Filters and time ranges

- **Fact (docs):** The dashboard supports date ranges, chart intervals, comparisons, and filters that can be combined across sources, countries, pages, campaigns, goals, devices, and other dimensions ([dashboard overview](https://plausible.io/docs/guided-tour), [filter and segment docs](https://plausible.io/docs/filters-segments), [comparison docs](https://plausible.io/docs/compare-stats)).
- **Fact (source):** The shared-link renderer supplies the normal dashboard and the internal query route parses date and filter parameters. The source does not add a per-link date-range restriction; the special required check is for a limited segment ([shared-link rendering](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/controllers/stats_controller.ex), [dashboard query controller](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/controllers/api/stats_controller.ex)).
- **Unavailable behavior:** I found no official control for limiting a public/shared link to a fixed date range, fixed chart interval, fixed comparison period, or fixed set of viewer-added filters. Plausible's documented link-level narrowing control is the required site segment ([shared-link docs](https://plausible.io/docs/shared-links)).

### Exports and programmatic access

- **Fact (docs):** The dashboard's quick export follows the selected date range and audience filters, returns a ZIP of CSV reports, limits individual reports to 300 entries and page reports to 100 entries, and can include imported data where supported ([export docs](https://plausible.io/docs/export-stats)).
- **Fact (source/test):** The official test suite posts to `/api/stats/:domain/export` with a shared-link `auth` value and asserts a successful ZIP export. The router places that endpoint behind the same internal site-access authorization used by dashboard queries ([shared-link export test](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/test/plausible_web/controllers/api/stats_controller/dashboard_csv_export_test.exs), [router](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/router.ex)).
- **Fact (source/changelog):** Password-protected shared-link requests to internal stats APIs need the shared-link auth cookie; the official changelog records the fix for carrying that cookie to internal stats API requests ([CHANGELOG](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/CHANGELOG.md)).
- **Fact (docs):** The full historical export is a separate site-settings operation, is not segmentable, and gives the owner a 24-hour download window after the export is ready. Plausible documents scheduled raw event exports as an Enterprise service rather than as a public/shared dashboard capability ([export docs](https://plausible.io/docs/export-stats), [data access docs](https://plausible.io/docs/data-access)).
- **Fact (docs):** The Stats API is separately authenticated with an API key in an `Authorization` header. A shared-link slug is not a Stats API key ([Stats API authentication](https://plausible.io/docs/stats-api), [Sites API shared-link response](https://plausible.io/docs/sites-api)).
- **Inference for Cimi:** If Cimi wants a recipient to read only a small set of metrics, embedding or sharing the full Plausible dashboard is not sufficient. A custom UI backed by a separately controlled API is the narrower design, but it is outside Plausible's public/shared-link contract.

## Indexing, Embedding, and URL Leakage Controls

- **Fact (source):** The shared-link router pipeline applies `NoRobots`; the shared-link renderer explicitly emits `x-robots-tag: noindex, nofollow`. The normal dashboard controller also emits `noindex, nofollow` ([router shared-link pipeline](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/router.ex), [NoRobots plug](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/plugs/no_robots.ex), [dashboard controller](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/controllers/stats_controller.ex)).
- **Fact (source):** The Community Edition's checked-in `robots.txt` disallows all user agents from all paths. Plausible Cloud's current `https://plausible.io/robots.txt` contains a sitemap declaration, but the application-level noindex response still applies to the normal/shared dashboard paths ([Community Edition robots.txt](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/priv/static/robots.txt), [Plausible Cloud robots.txt](https://plausible.io/robots.txt), [NoRobots plug](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/plugs/no_robots.ex)).
- **Fact:** `noindex` and `robots.txt` are crawler instructions, not access control. Anyone holding an open shared link can still request it; public visibility is intentionally open ([visibility docs](https://plausible.io/docs/visibility), [shared-link docs](https://plausible.io/docs/shared-links)).
- **Fact (docs/source):** An unprotected shared link can be embedded in an iframe. The shared-link route removes `x-frame-options` and sets embed-oriented headers including `strict-origin-when-cross-origin`; password-protected links cannot be embedded according to the docs ([embed docs](https://plausible.io/docs/embed-dashboard), [shared-link route and headers](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/controllers/stats_controller.ex), [secure embed headers](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/plugs/secure_embed_headers.ex)).
- **Inference for Cimi:** Because the shared slug is in the URL, Cimi should treat browser history, copied URLs, screenshots, logs, and third-party referrer handling as part of the disclosure threat model. Plausible's source sets a cross-origin referrer policy, but the cited sources do not promise that every intermediary will redact or avoid logging the URL.

## Revocation and Rotation

### Public visibility

- **Fact:** Turning public visibility off changes the site back to private, and the normal authorization path no longer assigns the `:public` role merely from the site flag ([visibility docs](https://plausible.io/docs/visibility), [site controller](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/controllers/site_controller.ex), [authorization plug](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/plugs/authorize_site_access.ex)).
- **Fact (source):** `make_private` only updates `site.public`; it does not delete separately-created shared-link rows ([site schema](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible/site.ex), [site controller](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/controllers/site_controller.ex)).
- **Inference for Cimi:** Making a Site private revokes the tokenless public dashboard, but it should not be treated as revoking every separately-created shared link for that Site.

### Shared links

- **Fact (docs):** An owner removes a shared link with the trash-can action. The documentation says the link can be edited for its name and segment restriction ([shared-link docs](https://plausible.io/docs/shared-links)).
- **Fact (source):** Access first looks up the slug for the requested site. If the row is absent, the shared-link controller returns a 404; a previously issued signed password cookie cannot pass the row lookup without the row ([shared-link lookup](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/controllers/stats_controller.ex), [authorization plug](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/plugs/authorize_site_access.ex)).
- **Fact (source):** Updating a shared link changes name/password fields accepted by the changeset and its segment association, but the shown creation/edit form does not provide a slug-rotation operation. New links generate a new Nanoid slug ([shared-link changeset](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible/site/shared_link.ex), [shared-link settings form](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/live/shared_link_settings/form.ex), [shared-link creation](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible/sites.ex)).
- **Unavailable behavior:** The reviewed docs and source do not specify an automatic expiry for an unprotected shared-link slug. The stored schema has timestamps but no expiry field, and access lookup is based on slug existence ([shared-link schema](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible/site/shared_link.ex), [shared-link lookup](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/controllers/stats_controller.ex)).
- **Unavailable behavior:** The reviewed docs do not specify whether deletion purges already-cached HTML/JSON or invalidates copies already downloaded by a recipient. Server-side authorization should deny subsequent requests, but cache and downloaded-copy behavior is not defined in the public contract.

## Rate Limits and Caching

- **Fact (source):** Dashboard query, export, current-visitors, and filter-suggestion routes are in the `internal_stats_api` pipeline and use site/shared-link authorization. That pipeline and the corresponding ordinary query/export functions do not declare the API-key rate limiter used by the public Stats API ([router](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/router.ex), [internal stats controller](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/controllers/api/stats_controller.ex), [site authorization](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/plugs/authorize_site_access.ex)).
- **Careful conclusion:** I found no Plausible-documented per-public-link or per-shared-link request limit. The source reviewed here shows no dedicated per-link limiter, but that does not rule out infrastructure-level limits outside this repository.
- **Fact (separate API):** The documented Stats API uses a Bearer API key and has a default limit of 600 requests per hour; the source also enforces hourly and short-burst limits per API key. This is not the authentication or rate-limit model of an anonymous dashboard link ([Stats API docs](https://plausible.io/docs/stats-api), [public API authorization](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/plugs/authorize_public_api.ex)).
- **Fact (source comment):** The dashboard controller says client-side caching of historical data was considered but that no client-side caching had been implemented in the referenced source snapshot ([dashboard controller module documentation](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/controllers/stats_controller.ex)).
- **Fact (source):** The shared-link pipeline adds secure/embed headers, not a documented cache lifetime or revalidation policy ([shared-link pipeline](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/router.ex), [secure embed headers](https://github.com/plausible/analytics/blob/9cc669b97ece3ecd37fcb3950791cb3873d7944d/lib/plausible_web/plugs/secure_embed_headers.ex)).
- **Unavailable behavior:** I found no official public/shared-dashboard guarantee for CDN caching, browser caching, response freshness, stale data windows, cache purge, or revocation propagation through intermediaries. Cimi should not derive those guarantees from the dashboard URL alone.

## Privacy Controls and Disclosure Risks

- **Fact (official data policy):** Plausible says its visitor analytics are aggregated, isolated to one day/site/device, do not use persistent identifiers, discard raw IP and full User-Agent values, and collect page URL host/path, referrer, derived browser/OS/device, and derived country/region/city ([official data policy](https://plausible.io/data-policy)).
- **Fact (official docs):** Custom properties can become dashboard dimensions, but Plausible prohibits PII such as names, usernames, email addresses, precise locations, IP addresses, cookie IDs, advertising IDs, and other pseudonymous end-user identifiers in custom properties ([custom properties docs](https://plausible.io/docs/custom-props/introduction)).
- **Fact (official privacy policy):** Plausible distinguishes website visitor data from customer account data; the persistent first-party login cookie is for customer account sessions, not the public/shared dashboard recipient model ([official privacy policy](https://plausible.io/privacy)).
- **Inference for Cimi:** Plausible's aggregate analytics privacy posture reduces the sensitivity of a shared dashboard, but it does not make every dashboard value harmless. Page paths, referrers, campaign values, custom properties, goal names, revenue, and small audience segments can still disclose business-sensitive information.
- **Fact (docs):** A password and a required segment are the documented per-shared-link privacy controls. Public visibility has no per-recipient password or segment boundary ([visibility docs](https://plausible.io/docs/visibility), [shared-link docs](https://plausible.io/docs/shared-links)).
- **Unavailable behavior:** I found no documented viewer identity, recipient-specific access list, viewer audit trail, per-link export disable switch, minimum-count suppression/k-anonymity rule, or dashboard-level consent prompt for public/shared recipients in the reviewed first-party sources.

## Implications for Cimi Issue #8

1. **Public disclosure:** Model public access as a Site-wide, tokenless mode. It is simple to revoke for future requests by changing the Site flag, but it cannot distinguish recipients or rotate a per-recipient secret.
2. **Private sharing:** Model an unprotected shared link as a bearer capability scoped to one Site. Require a password or Cimi authentication if forwarding the URL must not be sufficient.
3. **Scope enforcement:** If Cimi offers segment-limited sharing, enforce the base filter server-side and preserve it across query and export routes. A UI-only hidden-filter approach would not match the source behavior needed for the boundary.
4. **Exports:** Treat export as part of dashboard disclosure. A viewer who can use the shared dashboard can obtain filtered aggregate CSVs; do not define "view-only" as "cannot copy or export" unless Cimi adds its own access layer.
5. **Operational contract:** Cimi must define its own TTL, token rotation, viewer audit, rate limiting, cache invalidation, and small-count privacy rules if those are Hard Gates. Plausible's public/shared dashboard contract does not document them.
