# Umami public/shared dashboard and data-access research

**For:** Cimi issue [#8](https://github.com/falentio/cimi/issues/8)
**Checked:** 2026-08-23
**Version scope:** Umami `v3.3.1`, the current official source release checked here ([release](https://github.com/umami-software/umami/releases/tag/v3.3.1)). Documentation claims below are from the official Umami documentation; implementation claims are pinned to the official `v3.3.1` source tree.

Only Umami-owned documentation, the official Umami source repository, official GitHub security advisories/releases, and Umami's official privacy policy are used.

## Executive findings

- **Fact:** Umami supports public website share URLs and public board links. Anyone who has the link can view the shared data without an Umami login; the product describes the view as read-only. ([public dashboard guide](https://docs.umami.is/docs/guides/create-a-public-dashboard), [board sharing](https://docs.umami.is/docs/add-a-board))
- **Fact:** A share URL is a bearer capability. In `v3.3.1`, the public slug endpoint returns a signed JWT containing the share type, entity IDs, and share parameters. The browser sends it in `x-umami-share-token` together with `x-umami-share-context`. ([share slug route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/share/%5Bslug%5D/route.ts), [auth](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/lib/auth.ts), [client API hook](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/components/hooks/useApi.ts))
- **Fact:** Website shares are page-level allowlists, not field-level redaction. Available sections include overview, events, sessions, realtime, performance, compare, breakdown, goals, funnels, journeys, retention, UTM, revenue, and attribution. ([share permissions](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/permissions/share.ts), [share page](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/share/%5Bslug%5D/%5B%5B...path%5D%5D/SharePage.tsx))
- **Fact:** The Sessions section is potentially detailed: Umami documents country, browser, OS, pages viewed, visitor profiles, linked sessions, and custom session properties. If Cimi sends Distinct IDs or session properties, those values can become part of the publicly accessible session view. ([Sessions](https://docs.umami.is/docs/sessions), [metric definitions](https://docs.umami.is/docs/metric-definitions), [Distinct IDs](https://docs.umami.is/docs/distinct-ids), [session detail route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/websites/%5BwebsiteId%5D/sessions/%5BsessionId%5D/route.ts))
- **Fact:** Public viewers can change the date range. Filters are enabled by default but can be disabled in the share parameters with `allowFilter: false`; in `v3.3.1`, that option primarily controls the standard UI and filter propagation. ([filters](https://docs.umami.is/docs/filters), [website controls](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/%28main%29/websites/%5BwebsiteId%5D/WebsiteControls.tsx), [share navigation](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/share/%5Bslug%5D/%5B%5B...path%5D%5D/ShareNav.tsx), [filter hook](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/components/hooks/useFilterParameters.ts))
- **Fact:** The standard public website/board views do not expose the download button, and the export API requires an authenticated user rather than only a share token. ([website page](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/%28main%29/websites/%5BwebsiteId%5D/WebsitePage.tsx), [export route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/websites/%5BwebsiteId%5D/export/route.ts), [authenticated-only permission](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/permissions/share.ts))
- **Fact:** Share pages are excluded from normal indexing in the tagged source: the global HTML metadata is `noindex,nofollow`, and `robots.txt` disallows everything except `/q/`. This is crawler guidance, not access control. ([root layout](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/layout.tsx), [`public/robots.txt`](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/public/robots.txt))
- **Inference:** Deleting or changing a share row prevents new visitors from obtaining the slug's token, but does not revoke an already issued share JWT in `v3.3.1`. The JWT has no `exp` claim, and share authorization uses token claims without looking up the share row on each analytics request. ([share slug route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/share/%5Bslug%5D/route.ts), [JWT helpers](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/lib/jwt.ts), [share auth](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/lib/auth.ts), [share permissions](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/permissions/share.ts), [share deletion/update API](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/share/id/%5BshareId%5D/route.ts))
- **Unavailable:** I found no public-share-specific rate limit, token TTL, cache TTL, viewer authentication mode, or privacy/retention policy in the official public-share documentation. The explicit data-access limit found is for Umami Cloud API keys, not share links; the v3.3.0 release also mentions rate limiting for repeated failed 2FA attempts, which is unrelated to public sharing. ([Cloud API key limits](https://docs.umami.is/docs/cloud/api-key), [share API reference](https://docs.umami.is/docs/api/share), [v3.3.0 release notes](https://github.com/umami-software/umami/releases/tag/v3.3.0))

## 1. Link and token model

### Website share URLs

**Documented facts:**

- A website owner creates a Share URL from the website's edit screen, selects the views, and distributes a generated URL such as `/share/abc123/My-Website`. Umami says anyone with the link can access it without logging in. ([create a public dashboard](https://docs.umami.is/docs/guides/create-a-public-dashboard), [enable Share URL](https://docs.umami.is/docs/enable-share-url))
- Website share views are selected from Traffic, Behavior, and Growth categories. The official list is Overview, Events, Sessions, Realtime, Compare, Breakdown, Goals, Funnels, Journeys, Retention, UTM, Revenue, and Attribution. ([enable Share URL](https://docs.umami.is/docs/enable-share-url))
- Share URLs are documented as permanent until deleted. ([create a public dashboard](https://docs.umami.is/docs/guides/create-a-public-dashboard))

**Source behavior in `v3.3.1`:**

- The public `GET /api/share/:slug` route performs a share-row lookup by slug and does not call `parseRequest` for user authentication. If the row and underlying entity exist, it returns the share ID, share type, parameters, entity identifiers, and a token. ([`src/app/api/share/[slug]/route.ts`](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/share/%5Bslug%5D/route.ts))
- The token is created with `createToken({ ...data, type: SHARE_TOKEN_TYPE }, secret())`. `createToken` calls `jsonwebtoken.sign` without an expiry option in this route. ([share slug route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/share/%5Bslug%5D/route.ts), [JWT helper](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/lib/jwt.ts), [constants](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/lib/constants.ts))
- The generated website slug is 16 cryptographically selected alphanumeric characters when created through the website-share endpoint. The general share API accepts a caller-supplied slug with a maximum length of 100 in its request schema. ([website share creation](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/websites/%5BwebsiteId%5D/shares/route.ts), [random string generator](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/lib/generate.ts), [general share creation](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/share/route.ts))
- The client sends the returned token as `x-umami-share-token` and adds `x-umami-share-context: 1`. `checkAuth` accepts an unauthenticated request only when a valid share token is present and the share-context header is present. ([client API hook](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/components/hooks/useApi.ts), [auth](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/lib/auth.ts))

**Interpretation:** The URL slug is the discovery credential and the JWT is the API bearer credential. Possession of either the URL or a copied token should be treated as access to the configured share scope; there is no second viewer identity, password, email challenge, or per-viewer audit identity in the documented flow. The last sentence is an inference from the public route, token flow, and documentation, not a stated Umami guarantee. ([public dashboard guide](https://docs.umami.is/docs/guides/create-a-public-dashboard), [share slug route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/share/%5Bslug%5D/route.ts), [auth](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/lib/auth.ts))

### Board share links

- Boards can be website-scoped or mixed, and the official guide says a board share link can be viewed without login. ([create a public dashboard](https://docs.umami.is/docs/guides/create-a-public-dashboard), [add a board](https://docs.umami.is/docs/add-a-board))
- A board share token contains `boardId` plus the website, pixel, and link IDs that the share route authorizes for the board. The share route filters board entity IDs against the board owner's/team's access before placing them in the token. ([share slug route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/share/%5Bslug%5D/route.ts), [board permissions](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/permissions/board.ts), [board entity extraction](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/lib/boards.ts))
- The board component registry defines the data that a board can render, including metric bars, charts, metric tables, world maps, weekly traffic, custom events, UTM, revenue, realtime, goals, funnels, and text blocks. It does not define a public board component for the full Sessions screen or session replay. ([board component registry](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/%28main%29/boards/boardComponentRegistry.tsx))
- A shared board is rendered with `BoardViewPage` and its default controls. For a website-bound board, those controls include the date selector and the standard filter UI unless `allowFilter` is false in the share parameters. ([share page](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/share/%5Bslug%5D/%5B%5B...path%5D%5D/SharePage.tsx), [board view](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/%28main%29/boards/%5BboardId%5D/BoardViewPage.tsx), [board controls](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/%28main%29/boards/%5BboardId%5D/BoardControls.tsx), [website controls](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/%28main%29/websites/%5BwebsiteId%5D/WebsiteControls.tsx))

## 2. Public versus authenticated access

| Operation | Public share credential | Evidence |
| --- | --- | --- |
| Resolve `/share/:slug` to share metadata and a token | Yes, if the slug exists | [`src/app/api/share/[slug]/route.ts`](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/share/%5Bslug%5D/route.ts) has no authenticated `parseRequest` call; the public guide says no login is required. |
| Read an enabled website section | Yes, with the share token and share context | [`canViewWebsiteSection`](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/permissions/share.ts) accepts the share-token entity and enabled section. |
| Read a board | Yes, for the board in the token | [`canViewBoard`](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/permissions/board.ts) accepts a matching `boardId` share claim. |
| Create, update, or delete shares | No, authenticated owner/team permission required | [share management routes](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/share/id/%5BshareId%5D/route.ts), [share creation](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/share/route.ts) |
| Export website data through `/export` | No, public share token is not enough in `v3.3.1` | [export route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/websites/%5BwebsiteId%5D/export/route.ts), [authenticated-only check](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/permissions/share.ts) |

The public model is therefore open-by-link, not authenticated sharing. Umami's ordinary API documentation describes authenticated self-hosted API calls and Cloud API-key calls separately from public share URLs. ([API overview](https://docs.umami.is/docs/api), [API authentication](https://docs.umami.is/docs/api/authentication), [public dashboard guide](https://docs.umami.is/docs/guides/create-a-public-dashboard))

## 3. Data scope and privacy exposure

### Website shares

- The share token's `parameters` are a flexible object, but the typed share parameters define only `allowFilter`, `theme`, and boolean section flags. There is no field-level masking or column allowlist in the share model. ([share types](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/lib/types.ts), [share permissions](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/permissions/share.ts))
- The section permission check binds a token to one website, pixel, link, or a board's filtered entity IDs, then checks the requested section. If any section flag is present, a public website request must name a section whose flag is `true`; if no section flags are present, the source allows the section by default. ([share permissions](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/permissions/share.ts))
- `GET /sessions` returns session details for the requested date/filter range when the Sessions section is enabled. `GET /sessions/:sessionId`, activity, and properties use the same public section authorization, so a viewer who can reach Sessions can drill into session details. ([sessions route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/websites/%5BwebsiteId%5D/sessions/route.ts), [session detail route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/websites/%5BwebsiteId%5D/sessions/%5BsessionId%5D/route.ts), [session activity route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/websites/%5BwebsiteId%5D/sessions/%5BsessionId%5D/activity/route.ts), [session properties route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/websites/%5BwebsiteId%5D/sessions/%5BsessionId%5D/properties/route.ts))
- The official Sessions documentation says a row can show country, browser, operating system, and pages viewed; profiles can show activity history, linked sessions, and saved custom properties. ([Sessions](https://docs.umami.is/docs/sessions))
- The Events section can expose event rows and custom event data. The official Events API documents event URLs, referrers, location/device fields, event names, and event properties as available API data. ([Events API](https://docs.umami.is/docs/api/events), [events route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/websites/%5BwebsiteId%5D/events/route.ts))

### Identifiers and custom data

- Umami describes default analytics as anonymous and cookie-free, but its documented Distinct ID feature accepts an ID up to 50 characters, including an email, and its identify guide shows names, plans, and companies as optional session data. ([FAQ](https://docs.umami.is/docs/faq), [Distinct IDs](https://docs.umami.is/docs/distinct-ids), [identify guide](https://docs.umami.is/docs/guides/identify-logged-in-users))
- The official metric definitions list Distinct ID as a session metric, and the Sessions documentation says custom session data is visible in profiles and can be used for filtering. ([metric definitions](https://docs.umami.is/docs/metric-definitions), [Sessions](https://docs.umami.is/docs/sessions))
- **Inference:** Enabling Sessions, Events, or property-capable reports on a public link is not equivalent to sharing only anonymous aggregates. Cimi would need to prohibit or redact personal identifiers, URLs, event properties, session properties, and revenue values before enabling those sections if the dashboard is intended to be broadly public. ([share permissions](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/permissions/share.ts), [metric definitions](https://docs.umami.is/docs/metric-definitions), [identify guide](https://docs.umami.is/docs/guides/identify-logged-in-users))

### Boards

- A board lets the owner choose individual components and bind them to websites, pixels, and links; the public view receives the board definition and authorized entity IDs. ([create a public dashboard](https://docs.umami.is/docs/guides/create-a-public-dashboard), [board registry](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/%28main%29/boards/boardComponentRegistry.tsx), [share slug route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/share/%5Bslug%5D/route.ts))
- **Inference:** Boards provide a narrower presentation surface than enabling the full website navigation, but they are still not a privacy transformation. A chart or table can expose any dimension/value the owner configured, and board text blocks can intentionally publish arbitrary text. ([board registry](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/%28main%29/boards/boardComponentRegistry.tsx))

## 4. Filters and time ranges

### Documented and UI behavior

- Umami documents universal filtering: the website date range and filters can be applied across screens and reports. Documented filters include paths, query strings, titles, referrers, country, region, city, browser, OS, device, UTM fields, hostname, Distinct ID, tags, events, session properties, and event properties. ([Filters](https://docs.umami.is/docs/filters))
- In `v3.3.1`, a public website page renders `WebsiteControls` with date filtering enabled. The filter control is shown unless the share parameter is exactly `allowFilter: false`; the date control is independent of that flag. ([website page](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/%28main%29/websites/%5BwebsiteId%5D/WebsitePage.tsx), [website controls](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/%28main%29/websites/%5BwebsiteId%5D/WebsiteControls.tsx), [share helper](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/lib/share.ts))
- The share navigation preserves filter query parameters when filtering is allowed and removes standard filter parameters when it is disabled. The filter hook likewise omits filter, segment, cohort, bounce, and match parameters when `allowFilter` is false. ([share navigation](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/share/%5Bslug%5D/%5B%5B...path%5D%5D/ShareNav.tsx), [filter hook](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/components/hooks/useFilterParameters.ts), [share helper](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/lib/share.ts))

### Server-side limits and caveat

- The stats, events, and sessions routes accept `startAt`/`endAt` timestamps plus filter parameters, and section authorization is checked before querying. Realtime is an exception: its route always calculates the previous 30 minutes and ignores a caller-supplied historical range. ([stats route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/websites/%5BwebsiteId%5D/stats/route.ts), [events route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/websites/%5BwebsiteId%5D/events/route.ts), [sessions route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/websites/%5BwebsiteId%5D/sessions/route.ts), [realtime route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/realtime/%5BwebsiteId%5D/route.ts), [date/filter schemas](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/lib/schema.ts), [realtime constants](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/lib/constants.ts))
- **Inference/caveat:** `allowFilter: false` is enforced by the standard share UI and by some filter-related permission paths, but the main stats/events/sessions routes shown above call `canViewWebsiteSection`, not `canViewSharedWebsiteFilters`, and still parse filter query parameters. A hostile viewer should therefore not be assumed unable to submit manual filter parameters merely because the UI hides the filter controls. ([share permissions](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/permissions/share.ts), [stats route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/websites/%5BwebsiteId%5D/stats/route.ts), [events route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/websites/%5BwebsiteId%5D/events/route.ts), [sessions route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/websites/%5BwebsiteId%5D/sessions/route.ts))
- **Unavailable:** The official docs do not define a public-share-specific maximum date span, a fixed historical cutoff, or a way to pin a share to an immutable date range. The source accepts date ranges subject to the ordinary website/cloud/reset data rules, not a public-share policy. ([Filters](https://docs.umami.is/docs/filters), [date/filter schemas](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/lib/schema.ts), [request date handling](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/lib/request.ts))

## 5. Exports and programmatic access

- The official Cloud export guide describes an authenticated Settings > Data export that includes all collected analytics for one website, such as page views, events, sessions, and event data; Umami sends a compressed CSV download link by email. This is account export, not public-share export. ([Cloud export](https://docs.umami.is/docs/cloud/export-data))
- In `v3.3.1`, the website export route accepts date/filter parameters but calls `canViewAuthenticatedWebsite`, which returns false when there is no authenticated `auth.user`. A share token alone therefore fails that authorization check. ([export route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/websites/%5BwebsiteId%5D/export/route.ts), [permission implementation](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/permissions/share.ts))
- The standard public website page leaves `allowDownload` at its default `false`, and the shared board page also uses controls whose `allowDownload` default is `false`. The normal public UI consequently has no download button. ([website page](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/%28main%29/websites/%5BwebsiteId%5D/WebsitePage.tsx), [website controls](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/%28main%29/websites/%5BwebsiteId%5D/WebsiteControls.tsx), [board controls](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/%28main%29/boards/%5BboardId%5D/BoardControls.tsx))
- **Unavailable:** I found no documented public-link export endpoint, export-specific scope, export audit log, or export rate limit. Treat public viewers as able to copy or query whatever the enabled views reveal, even when Umami's built-in export endpoint is authenticated-only. ([API overview](https://docs.umami.is/docs/api), [share API](https://docs.umami.is/docs/api/share), [export route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/websites/%5BwebsiteId%5D/export/route.ts))

## 6. Indexing, embedding, caching, and rate limits

### Indexing and robots

- The tagged source emits `<meta name="robots" content="noindex,nofollow">` from the root layout, which also wraps share pages. ([root layout](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/layout.tsx), [share layout](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/share/%5Bslug%5D/layout.tsx))
- `public/robots.txt` says `User-agent: *`, `Allow: /q/`, and `Disallow: /`. Since public shares are under `/share/`, compliant crawlers are instructed not to crawl them. ([`public/robots.txt`](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/public/robots.txt))
- **Inference:** These controls reduce normal search discovery but do not protect a leaked URL or token. Robots directives and `noindex` are not authorization checks. ([robots.txt](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/public/robots.txt), [share auth](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/lib/auth.ts))

### Embedding

- Umami officially supports embedding a share URL in an iframe and instructs operators to set `ALLOWED_FRAME_URLS` to permit the embedding origin. ([public dashboard guide](https://docs.umami.is/docs/guides/create-a-public-dashboard), [embed guide](https://docs.umami.is/docs/guides/embed-analytics-in-your-app))
- The source builds `Content-Security-Policy: frame-ancestors` from `'self'` plus `ALLOWED_FRAME_URLS`; the Docker proxy applies the policy at runtime so the environment value does not require an image rebuild. ([CSP builder](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/lib/csp.ts), [Docker proxy](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/docker/proxy.ts))
- **Inference:** `ALLOWED_FRAME_URLS` controls where the page may be framed, not who can open the share URL directly. It is an embedding-origin control, not a viewer access list. ([CSP builder](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/lib/csp.ts), [public dashboard guide](https://docs.umami.is/docs/guides/create-a-public-dashboard))

### Caching

- The tagged Next.js configuration and Docker proxy set `Cache-Control: no-cache` for `/api/:path*`, which includes share metadata and analytics API responses. The browser fetch helper also sets `cache: 'no-cache'`. ([Next.js config](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/next.config.ts), [Docker proxy](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/docker/proxy.ts), [fetch helper](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/lib/fetch.ts))
- **Unavailable:** There is no documented public-share cache TTL, stale-while-revalidate policy, CDN behavior, or guarantee that a deployment's reverse proxy honors these headers. The source's `no-cache` intent should not be treated as `no-store` or as a revocation mechanism. ([Next.js config](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/next.config.ts), [Docker proxy](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/docker/proxy.ts))

### Rate limits

- Umami documents a limit of 50 calls every 15 seconds for each Umami Cloud API key. That credential type is distinct from the public share JWT. ([Cloud API key](https://docs.umami.is/docs/cloud/api-key))
- **Unavailable:** I found no equivalent public-share token limit, per-IP limit, concurrency limit, or `Retry-After` contract in the official share documentation or the pinned share routes. Self-hosted operators may need to enforce such limits at a reverse proxy or application edge. ([share API](https://docs.umami.is/docs/api/share), [share slug route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/share/%5Bslug%5D/route.ts), [Next.js API headers](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/next.config.ts))

## 7. Revocation, rotation, and security caveats

### Share-row management

- Share management is authenticated: the create/update/delete routes call `parseRequest`, then require update/delete permission for the underlying entity. Deleting a share deletes its database row; updating can change its slug and parameters. ([share management route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/share/id/%5BshareId%5D/route.ts), [general share creation](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/share/route.ts), [website share management](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/websites/%5BwebsiteId%5D/shares/route.ts))
- **Fact:** After a share row is deleted, a new request to its slug cannot receive a token because the public slug route no longer finds the row. ([share slug route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/share/%5Bslug%5D/route.ts))
- **Inference:** A previously issued token remains usable until its signature stops verifying, because `parseShareToken` verifies the JWT and checks its type, while the share permissions use claims such as `websiteId`, `websiteIds`, `boardId`, and `parameters`; they do not re-fetch the share row. The token has no expiry claim in the minting path. ([share slug route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/share/%5Bslug%5D/route.ts), [JWT helper](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/lib/jwt.ts), [auth](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/lib/auth.ts), [share permissions](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/permissions/share.ts))
- **Inference:** Updating the slug or parameters changes what new slug resolution returns, but does not provide per-token revocation for already issued tokens. Changing `APP_SECRET` changes the signing secret and would invalidate all Umami JWTs derived from it, not only one share; the source does not provide a share-only token-rotation endpoint. ([share update route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/share/id/%5BshareId%5D/route.ts), [crypto secret](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/lib/crypto.ts), [JWT helper](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/lib/jwt.ts))
- **Unavailable:** No public-share expiry, per-link revocation list, token rotation button/API, viewer audit trail, or revocation propagation SLA is documented. ([public dashboard guide](https://docs.umami.is/docs/guides/create-a-public-dashboard), [share API](https://docs.umami.is/docs/api/share))

### Security advisories and source conflict

- The official advisory [GHSA-8www-cffh-4q98](https://github.com/umami-software/umami/security/advisories/GHSA-8www-cffh-4q98) says versions before `2.3.0` allowed anyone with a share link to reset website data and identifies `2.3.1` as patched. That historical issue is outside the `v3.3.1` affected-version range stated by the advisory.
- A separate official advisory [GHSA-3xx8-742v-m4mq](https://github.com/umami-software/umami/security/advisories/GHSA-3xx8-742v-m4mq), published 2026-06-30, claims versions `>= 2.3.1` through the latest release are affected because a cache JWT from `/api/send` can be replayed as a share token and used to read/export analytics. It states that no patched version is available.
- **Conflicting primary evidence:** The tagged `v3.3.1` source explicitly mints share tokens with `type: 'share'` and rejects tokens whose type is not `SHARE_TOKEN_TYPE`; the official `v3.2.0` release notes also say it fixed share-token confusion vulnerabilities. ([tagged auth source](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/lib/auth.ts), [tagged share route](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/api/share/%5Bslug%5D/route.ts), [v3.2.0 release notes](https://github.com/umami-software/umami/releases/tag/v3.2.0))
- **Conclusion:** The official advisory and the tagged source cannot be reconciled from the available primary material. This report does not claim that `v3.3.1` is exploitable, but Cimi should treat the advisory as an unresolved release/deployment risk and verify the exact deployed build and token behavior before making a public link available.

## 8. Privacy controls and gaps for Cimi

### Available controls

- Share owners can restrict website pages by section flags and can create a board containing only selected components. ([enable Share URL](https://docs.umami.is/docs/enable-share-url), [board registry](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/%28main%29/boards/boardComponentRegistry.tsx))
- Owners can disable the standard filter UI/propagation with `allowFilter: false`, although the server-side caveat above remains. ([share helper](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/lib/share.ts), [filter hook](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/components/hooks/useFilterParameters.ts))
- Operators can restrict iframe embedding with `ALLOWED_FRAME_URLS`; the default source policy only allows framing by the same origin. ([CSP builder](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/lib/csp.ts), [embed guide](https://docs.umami.is/docs/guides/embed-analytics-in-your-app))
- Search discovery is discouraged with `noindex,nofollow` and `robots.txt` disallow rules. ([root layout](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/app/layout.tsx), [`public/robots.txt`](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/public/robots.txt))

### Gaps and policy implications

- **Fact:** Umami's product documentation presents default tracking as anonymous/cookie-free, but its own documentation supports sending Distinct IDs and custom session data, including potentially identifying values. ([FAQ](https://docs.umami.is/docs/faq), [Distinct IDs](https://docs.umami.is/docs/distinct-ids), [identify guide](https://docs.umami.is/docs/guides/identify-logged-in-users))
- **Inference:** Public sharing should be configured only after deciding whether Cimi permits Sessions, Distinct IDs, session properties, event properties, revenue, URL queries, referrers, city/region, and realtime data to leave the Cimi trust boundary. Page selection alone does not answer that question. ([Sessions](https://docs.umami.is/docs/sessions), [Filters](https://docs.umami.is/docs/filters), [metric definitions](https://docs.umami.is/docs/metric-definitions), [share permissions](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/permissions/share.ts))
- **Fact about Umami Cloud policy scope:** Umami's privacy policy describes Umami's own Services, rights, retention, deletion/anonymization, and security limitations. It does not define the public-share behavior or retention contract for a Cimi self-hosted deployment. ([Umami privacy policy](https://umami.is/privacy), [self-hosting/API overview](https://docs.umami.is/docs/api))
- **Unavailable:** I found no official public-share setting for consent gating, per-viewer authentication, password protection, IP allowlists, field masking, PII detection, viewer audit logs, retention override, or individual visitor deletion from a shared dashboard. ([share API](https://docs.umami.is/docs/api/share), [share types](https://raw.githubusercontent.com/umami-software/umami/v3.3.1/src/lib/types.ts), [public dashboard guide](https://docs.umami.is/docs/guides/create-a-public-dashboard))

## Cimi decision points

1. Treat a public Umami link as bearer access with no viewer authentication, not as a controlled team-sharing mechanism.
2. Prefer a board with aggregate components over enabling the Sessions or Events sections when the audience is untrusted.
3. Do not send Cimi user IDs, emails, names, free-form session properties, or sensitive event properties to an instance whose share links may be public.
4. Decide whether `allowFilter: false` is sufficient for the threat model; the tagged UI honors it, but the primary data routes do not consistently use it as a server-side filter denial.
5. Define revocation as a Cimi requirement. Umami's documented delete operation stops slug resolution, but the `v3.3.1` token design does not demonstrate immediate revocation of already copied tokens.
6. Add edge rate limiting and logging if public sharing is enabled, because no public-share limit or viewer audit contract is documented.
7. Resolve the conflicting official cache-token advisory against the exact Umami build Cimi would deploy before relying on public shares.
