# Rybbit Public and Shared Dashboard Research

Scope: Rybbit public/shared dashboard access and data access for Cimi issue #8. This report covers the Public Analytics site flag, private share links, the public link/token model, exposed data, filters and time ranges, exports, indexing, revocation, rate limits, caching, privacy controls, and audit contradictions. It does not evaluate Rybbit's ordinary authenticated team-access model except where it determines whether a shared request is allowed.

Sources are limited to official Rybbit documentation, official Rybbit privacy/security pages, the official Rybbit source repository present in this workspace, and direct observations of official Rybbit endpoints. The source snapshot is the `rybbit` repository at commit `64f8c4fb7f394bdfe9379717de8e6c21758b1ac2` (`2026-08-20`, remote `https://github.com/rybbit-io/rybbit`).

## Executive Findings

- **Fact:** Public Analytics is a site-wide anonymous read gate. When `sites.public` is true, the public-site access helper returns access without requiring a session, API key, or private key. [`site-settings`](https://rybbit.com/docs/site-settings#public-analytics), `rybbit/server/src/lib/auth-utils.ts:449-465`
- **Fact:** A private link is a single site-wide bearer secret. The browser puts the 12-hex-character key in the URL, then sends it as `x-private-key` to the API; the server compares it directly with the configured site key. [`Dashboard Embed`](https://rybbit.com/docs/embeds/dashboard#requirements), `rybbit/client/src/proxy.ts:64-75`, `rybbit/client/src/api/utils.ts:96-128`, `rybbit/server/src/lib/auth-utils.ts:467-470`
- **Fact:** Both mechanisms authorize the same broad `publicSite` read route families, including analytics, sessions, events, users, funnels, goals, session replay, and Google Search Console. The current PDF export route is intentionally different and requires authenticated site access. `rybbit/server/src/index.ts:212-240,351-425,427-444,502-509`
- **Fact:** The broad routes return per-session and per-event identifiers, custom properties, query strings, location fields, raw IP fields when stored, user traits, and complete rrweb replay payloads. `rybbit/server/src/api/analytics/sessions/getSessions.ts:10-53,110-180`, `rybbit/server/src/api/analytics/sessions/getSession.ts:5-41,75-143`, `rybbit/server/src/api/analytics/events/getEvents.ts:8-73`, `rybbit/server/src/services/replay/sessionReplayQueryService.ts:156-204`
- **Fact:** The separate Widget Embed is materially narrower: it exposes only a live count, a time series, and top countries, and its endpoint is cached for 60 seconds. [`Widget Embeds`](https://rybbit.com/docs/embeds/widget#requirements), `rybbit/server/src/api/sites/getEmbedStats.ts:6-15,38-47,79-102`
- **Inference:** Public Analytics and private dashboard links are unsafe defaults for Cimi data that may contain identifiers, traits, raw IPs, sensitive URL parameters, Google Search Console data, or session replay. A constrained aggregate widget is the only Rybbit sharing mode in this snapshot with an explicit narrow data contract. This inference follows from the route authorization and response fields above, not from a Rybbit claim.

### Public Analytics Flag

- **Fact:** Rybbit's site documentation describes Public Analytics as external read-only access and says viewers cannot edit settings, reports, funnels, or goals. [`Site settings`](https://rybbit.com/docs/site-settings#public-analytics)
- **Fact:** The implementation stores `public` as an ordinary site boolean and accepts it in the admin-only site-config update request. There is no audience, field, time-window, or viewer-specific setting adjacent to that boolean. `rybbit/server/src/db/postgres/schema.ts:75-102`, `rybbit/server/src/api/sites/updateSiteConfig.ts:5-12,54-64`, [`Update Site Config`](https://rybbit.com/docs/api/sites/update-config#request-body)
- **Fact:** Public-site authorization is a boolean access decision. It does not redact response fields or constrain query parameters after access is granted. `rybbit/server/src/lib/auth-utils.ts:449-480`, `rybbit/server/src/lib/auth-middleware.ts:283-318`
- **Fact:** The public route set includes overview metrics, time series, pages, errors, retention, sessions, session details, events, users, user detail, user traits, funnels, funnel analysis and step sessions, journeys, goals, performance, bots, and session replay. `rybbit/server/src/index.ts:351-425,427-433`
- **Fact:** Public-site access also covers `GET /sites/:siteId/gsc/status` and `GET /sites/:siteId/gsc/data`. `rybbit/server/src/index.ts:502-509`
- **Inference:** The phrase "read-only" describes mutation authority, not an aggregate-only privacy boundary. Several public `POST` routes perform read/query operations, such as funnel analysis and funnel-step session retrieval. `rybbit/server/src/index.ts:381-392`

### Private Link Key

- **Fact:** The official Dashboard Embed documentation says the private key is part of the path, private links are not publicly listed, anyone with the link can view the dashboard, and the URL should be treated as a shareable read-only secret. [`Dashboard Embed`](https://rybbit.com/docs/embeds/dashboard#requirements)
- **Fact:** The client accepts only a 12-character hexadecimal private-key segment, redirects `/{siteId}/{key}` to `/{siteId}/{key}/main`, and preserves the key in the path. `rybbit/client/src/lib/siteRoute.ts:1-18,26-46`, `rybbit/client/src/proxy.ts:64-75`
- **Fact:** The server generates the key with `randomBytes(6).toString("hex")`, which is 6 random bytes (48 bits before hexadecimal encoding) and 12 hexadecimal characters, then writes it directly to the `private_link_key` text column. The access check is an exact string comparison against the request's `x-private-key` header. `rybbit/server/src/services/sites/siteConfigurationLifecycle.ts:356-366`, `rybbit/server/src/db/postgres/schema.ts:100-102`, `rybbit/server/src/lib/auth-utils.ts:467-470`
- **Fact:** The private-key branch is evaluated before the bearer-scope fallback and returns `true` without checking a resource-specific scope. Therefore one valid private key is not an `analytics:read`-only key; it authorizes every route that uses the public-site chain. `rybbit/server/src/lib/auth-utils.ts:462-480`, `rybbit/server/src/index.ts:212-240,351-425`
- **Inference:** This is a bearer-token model, not a signed, audience-bound, expiring token model. That follows from the single stored string, exact equality check, and lack of expiry or audience fields; it is not a documented Rybbit token taxonomy.
- **Fact:** The `embed=true`, `theme`, and `hideSidebar` values are presentation parameters in the Dashboard Embed URL. The server authorization helper shown above checks the site flag, session, API key, and `x-private-key`; it does not use `embed` or `hideSidebar` to reduce data scope. [`Dashboard Embed`](https://rybbit.com/docs/embeds/dashboard#url-parameters), `rybbit/server/src/lib/auth-utils.ts:449-480`
- **Inference:** `hideSidebar=true` should not be treated as a security control. It changes navigation in the client, while direct callers can still address the public read APIs if they possess the private key.

## Data Exposed

The following are source-level response contracts for requests that pass the public-site helper. The same statements apply to a public site and to a valid private link unless a route is explicitly marked otherwise.

### Aggregated and Configuration Data

- **Fact:** Overview and metric APIs accept the site's common time/filter parameters and return traffic, page, device, location, referrer, event, and related analytics. The client export descriptor enumerates referrer/channel/UTM, page, device, location, overview time-series, event, and outbound-link reads. `rybbit/server/src/index.ts:351-361`, `rybbit/client/src/app/[site]/components/SubHeader/Export/exportCsv.ts:8-56`
- **Fact:** `GET /sites/:siteId/funnels` returns every saved funnel's name, steps, configuration, timestamps, and stored result summary through a public route. `rybbit/server/src/index.ts:381-384`, `rybbit/server/src/api/analytics/funnels/getFunnels.ts:16-40`
- **Fact:** `GET /sites/:siteId/goals` is public and its response type includes the goal name, goal type, goal configuration, creation time, and conversion totals. `rybbit/server/src/index.ts:387-392`, `rybbit/server/src/api/analytics/goals/getGoals.ts:12-22`
- **Fact:** `GET /sites/:siteId` is also behind the public-site chain and returns site metadata/configuration such as domain, organization ID, creator, Public Analytics, replay, IP tracking, and URL-parameter tracking flags, while omitting the private key in the handler's selected fields. `rybbit/server/src/index.ts:435-442`, `rybbit/server/src/api/sites/getSite.ts:29-57`

### Sessions, Users, and Events

- **Fact:** Session-list rows include session ID, device/user identifiers, identified user ID, traits, country/region/city, browser and OS versions, dimensions, referrer/channel, hostname, page title, query string, UTM values, entry/exit pages, counts, timestamps, raw `ip`, latitude, longitude, and replay presence. `rybbit/server/src/api/analytics/sessions/getSessions.ts:10-53,110-180`
- **Fact:** A session-detail response includes session metadata with raw `ip` and a paginated event timeline containing pathname, hostname, query string, page title, referrer, event type/name, and properties. `rybbit/server/src/api/analytics/sessions/getSession.ts:5-51,75-143,148-200`
- **Fact:** The event-log response includes timestamp, event and session IDs, anonymous and identified user IDs, JSON properties, pathname, query string, hostname, page title, referrer, browser/device fields, country/region/city, latitude, and longitude. `rybbit/server/src/api/analytics/events/getEvents.ts:8-73,77-145`
- **Fact:** User-list aggregation returns anonymous and identified IDs, traits, location/device fields, pageview/event/session counts, hostnames, and first/last-seen timestamps. User search can query Postgres traits by username, name, or email before reading the event aggregates. `rybbit/server/src/api/analytics/users/getUsers.ts:12-43,103-153,156-183`
- **Fact:** User detail includes identified traits, linked devices, raw IP in its event aggregation, locations, devices, Web Vitals, referrer/channel, entry page, UTM values, and first/last-seen timestamps. `rybbit/server/src/api/analytics/users/getUserInfo.ts:12-85,88-175`
- **Fact:** Funnel-step session retrieval is public and returns session rows with identified IDs, user/device/location fields, URL/query/UTM fields, timestamps, counts, raw IP, latitude, longitude, and then enriches the rows with traits. `rybbit/server/src/api/analytics/funnels/getFunnelStepSessions.ts:114-173,176-214`

### Session Replay

- **Fact:** The session-replay list route is public-site protected and supports time/filter parameters, pagination, user filtering, and minimum duration. `rybbit/server/src/index.ts:427-433`, `rybbit/server/src/services/replay/sessionReplayQueryService.ts:52-81,84-141`
- **Fact:** The replay-detail route returns metadata including identified user ID, location, device, referrer, page URL, and replay state, plus every stored replay event in timestamp/sequence order. `rybbit/server/src/services/replay/sessionReplayQueryService.ts:20-50,156-204`
- **Fact:** Official API documentation describes the detail response as the rrweb events and metadata needed to reconstruct the replay. [`Get Session Replay Events`](https://rybbit.com/docs/api/session-replay/events)
- **Fact:** Official session-replay documentation describes mouse movement, clicks, scrolls, navigation, form interactions, and sharing with a team; it says sensitive information is automatically masked and additional PII protection can be enabled. [`Session Replay`](https://rybbit.com/docs/feature-guides/session-replay#what-youll-see), [`Web SDK replay privacy`](https://rybbit.com/docs/sdks/web#privacy-configuration)
- **Inference:** Replay masking is an ingestion/recording control, not a sharing-layer redaction control. The public response service returns the stored rrweb stream without a second field-level privacy pass. `rybbit/server/src/services/replay/sessionReplayQueryService.ts:178-204`

### Google Search Console

- **Fact:** Public GSC status returns whether a site is connected and the connected `gscPropertyUrl`. `rybbit/server/src/api/gsc/status.ts:10-31`
- **Fact:** Public GSC data accepts caller-supplied `start_date`, `end_date`, and `dimension`, refreshes the site's stored Google token, calls Google's Search Analytics API for the connected property, and requests up to 1,000 rows. `rybbit/server/src/api/gsc/getData.ts:13-58`
- **Inference:** Enabling Public Analytics can therefore expose owner-connected Google Search Console-derived search data, not just Rybbit-collected web analytics. This is an unsafe exposure because the source applies the public-site guard to the GSC routes and the handler does not add a separate owner/session check. `rybbit/server/src/index.ts:502-509`, `rybbit/server/src/api/gsc/getData.ts:31-46`

## Filters and Time Ranges

- **Fact:** The official Stats API documentation defines date ranges, exact UTC datetime ranges, and relative `past_minutes_start`/`past_minutes_end` windows. It also documents JSON filter arrays with equals, not-equals, contains, regex, and numeric comparisons. [`Getting Started: common parameters`](https://rybbit.com/docs/api/getting-started#common-parameters)
- **Fact:** Public analytics routes use the same common time/filter query contract as authenticated analytics routes. For example, sessions, users, events, replay lists, funnel analysis, and funnel-step sessions all consume time and/or filter parameters. `rybbit/server/src/api/analytics/sessions/getSessions.ts:55-108`, `rybbit/server/src/api/analytics/users/getUsers.ts:31-73`, `rybbit/server/src/api/analytics/events/getEvents.ts:36-85`, `rybbit/server/src/services/replay/sessionReplayQueryService.ts:52-109`, `rybbit/server/src/api/analytics/funnels/getFunnelStepSessions.ts:20-40`
- **Fact:** The HTTP middleware rejects malformed or incomplete time parameters, but absent time parameters are explicitly allowed as an all-time query. `rybbit/server/src/index.ts:191-199`, `rybbit/server/src/api/analytics/utils/timeWindow.ts:39-43,82-86`
- **Contradiction:** The official Getting Started page says callers must provide one of the date, exact-datetime, or relative-time forms, while the current HTTP validator and query builder treat no time parameters as a legitimate all-time query. [`Getting Started`](https://rybbit.com/docs/api/getting-started#time-parameters), `rybbit/server/src/api/analytics/utils/timeWindow.ts:82-86`
- **Inference:** A public or private-link viewer can request the site's full retained history by omitting time parameters, subject to endpoint execution limits and the site's retention policy. This follows from public authorization plus the all-time query behavior; it is not limited to the date range shown when the link was generated.
- **Fact:** A session detail can return the full event timeline by default, with optional `limit`, `offset`, and a last-N-minutes parameter; replay detail takes no query parameters and returns the complete replay for the selected session. [`Get Session`](https://rybbit.com/docs/api/sessions/get#query-parameters), [`Get Session Replay Events`](https://rybbit.com/docs/api/session-replay/events#query-parameters), `rybbit/server/src/api/analytics/sessions/getSession.ts:54-64,110-143`, `rybbit/server/src/services/replay/sessionReplayQueryService.ts:156-204`
- **Fact:** Endpoint-level pagination limits are not an access boundary. The official docs expose page/limit/offset controls for sessions, users, replay lists, and funnel-step sessions, and the source interpolates those values into public query paths. [`Get Sessions`](https://rybbit.com/docs/api/sessions/list#query-parameters), [`Get Users`](https://rybbit.com/docs/api/users/list#query-parameters), [`Get Session Replays`](https://rybbit.com/docs/api/session-replay/list#query-parameters), [`Get Funnel Step Sessions`](https://rybbit.com/docs/api/funnels/step-sessions#query-parameters)

## Exports

- **Fact:** The dashboard's CSV export is client-side. It calls the same analytics read layer with the current site, time window, timezone, and filters, then creates a ZIP containing metric, overview, event, and outbound-link CSVs. `rybbit/client/src/app/[site]/components/SubHeader/Export/exportCsv.ts:37-56,65-85,115-127`
- **Fact:** `authedFetch` adds the private key header whenever the current URL contains a private key. Therefore the CSV export requests work through the public/private-link read routes rather than requiring a session. `rybbit/client/src/api/utils.ts:96-128`, `rybbit/client/src/api/installRequestContext.ts:5-12`
- **Fact:** The share/export component keeps the export control visible for a non-session viewer on desktop and calls CSV export without checking `canShare`; the share-only UI is withheld, but the export path is not. `rybbit/client/src/app/[site]/components/SubHeader/ShareExportButton.tsx:28-43,63-87,153-162`
- **Fact:** If GSC is connected, the CSV export also fetches GSC status and four dimensions (`query`, `page`, `country`, `device`) for the selected date range. `rybbit/client/src/app/[site]/components/SubHeader/Export/exportCsv.ts:58-63,87-113`, `rybbit/client/src/api/gsc/endpoints/data.ts:3-37`
- **Fact:** PDF export is not authorized by the public-site/private-key chain in this snapshot. The route is registered with `authAnalyticsRead`, which uses `requireSiteAccess` and accepts a session or API key, not the private-link fallback; the official PDF example also requires an Authorization bearer token. `rybbit/server/src/index.ts:215-217,424-425`, `rybbit/server/src/lib/auth-middleware.ts:192-227`, [`Export PDF Report`](https://rybbit.com/docs/api/sites/export-pdf#request)
- **Inference:** Rybbit's private-link dashboard should not be described as a general-purpose export link. CSV export is reachable through the public read APIs, while PDF export is an authenticated-only path and may be a UI contract mismatch for anonymous private-link viewers.

## Indexing and Robots Behavior

- **Fact:** The official Dashboard Embed docs say private links are not listed publicly, but that is an unlisted-secret statement, not a crawler policy. [`Dashboard Embed`](https://rybbit.com/docs/embeds/dashboard#requirements)
- **Fact:** The only `robots.ts` in the workspace snapshot is under the documentation site. It allows the documentation root, disallows its `/api/`, build, JSON, and query-parameter paths, and publishes a `rybbit.com` sitemap. `rybbit/docs/src/app/robots.ts:1-31`
- **Fact:** The application client has no `client/src/app/robots.ts` or `client/src/app/sitemap.ts` in this snapshot. Its root layout sets only the HTML language/body/providers and no robots metadata. `rybbit/client/src/app/layout.tsx:1-23`
- **Fact:** The client proxy applies `Cache-Control: no-store, max-age=0` to the redirects for `/siteId` and `/siteId/privateKey`, but it does not set `noindex`, `X-Robots-Tag`, or a crawler rule. `rybbit/client/src/proxy.ts:27-75`
- **Observation (official app, checked 2026-08-23):** `https://app.rybbit.io/robots.txt` and `https://app.rybbit.io/sitemap.xml` returned HTTP 200 `text/html` app-shell responses with private/no-store caching headers, rather than a robots rules document or XML sitemap. [`app robots.txt`](https://app.rybbit.io/robots.txt), [`app sitemap.xml`](https://app.rybbit.io/sitemap.xml)
- **Inference:** Shared dashboard URLs are not protected from discovery by robots directives in the inspected application deployment. The private-link key still acts as the access control, but a private URL should not be treated as safe merely because it is absent from a sitemap. A different reverse proxy or deployment may add crawler headers, so this is an audit result for the inspected snapshot/deployment rather than a universal Rybbit Cloud guarantee.

## Revocation, Rotation, and Staleness

- **Fact:** Admin/owner-only API operations generate or revoke the one private link. Generation replaces the stored key with a new 6-byte random value; revocation replaces it with `null`. [`Update Private Link Config`](https://rybbit.com/docs/api/sites/update-private-link), `rybbit/server/src/api/sites/updateSitePrivateLinkConfig.ts:5-35`, `rybbit/server/src/services/sites/siteConfigurationLifecycle.ts:356-366`
- **Fact:** Replacing or revoking the key invalidates the local site-config cache in the process handling the write. `rybbit/server/src/services/sites/siteConfigurationLifecycle.ts:360-365`, `rybbit/server/src/lib/siteConfig.ts:252-265`
- **Fact:** Site config reads have a one-minute TTL, and the source explicitly states that under `CLUSTER_WORKERS` a sibling worker may retain the pre-write value for up to that TTL. `rybbit/server/src/lib/siteConfig.ts:48-50,197-205`
- **Unsafe exposure:** Private-link revocation and Public Analytics disablement are not guaranteed to take effect immediately across a clustered deployment. A sibling worker can continue accepting an old private key or old public flag during the stale-cache interval. This is a source-documented implementation behavior, not a hypothetical cache concern. `rybbit/server/src/lib/siteConfig.ts:197-205`
- **Fact:** The source has one `privateLinkKey` column, not a collection of independently revocable keys, and the private-link API exposes only generate and revoke actions. `rybbit/server/src/db/postgres/schema.ts:100-102`, [`Update Private Link Config`](https://rybbit.com/docs/api/sites/update-private-link#request-body)
- **Inference:** Rotation is site-wide invalidation, not per-recipient revocation. Sharing a link with multiple recipients means changing the key revokes all recipients together, and there is no source-level per-recipient audit identity or expiry policy.

## Rate Limits and Caching

### Rate Limits

- **Fact:** The current source defines a 50-request burst bucket over 10 seconds, with a 5,000-request Standard daily quota and 25,000-request Pro daily quota when Cloud limiting is enabled; self-hosted daily limit is zero/unlimited. `rybbit/server/src/lib/const.ts:40-59`, `rybbit/server/src/lib/apiRateLimit.ts:42-53`
- **Fact:** Official Getting Started documentation describes the same Cloud burst/daily model and says self-hosted instances are not rate limited. [`Getting Started: rate limits`](https://rybbit.com/docs/api/getting-started#rate-limits-cloud-only)
- **Contradiction:** The official Sending Events page still documents API keys as limited to 500 requests per 10 minutes, which conflicts with the current Getting Started page and source constants. [`Sending Events`](https://rybbit.com/docs/api/sending-events#rate-limiting), [`Getting Started`](https://rybbit.com/docs/api/getting-started#rate-limits-cloud-only), `rybbit/server/src/lib/const.ts:51-54`
- **Fact:** The limiter is charged while resolving bearer API credentials. A request with no bearer token returns from `checkApiKey` without a rate-limit decision, and the public/private helper can authorize by site flag or `x-private-key` without bearer credentials. `rybbit/server/src/lib/auth-utils.ts:373-385,449-480`, `rybbit/server/src/lib/auth-middleware.ts:291-318`
- **Inference:** Anonymous Public Analytics traffic and private-link traffic are outside the documented bearer-key budget. The inspected public-site path has no equivalent per-IP, per-private-key, or per-link request limiter. Cloud edge protections may exist outside this repository, but they are not the Rybbit application-level control evidenced here.
- **Fact:** Authenticated bearer responses can carry rate-limit headers, but those headers are attached in the bearer-auth path. `rybbit/server/src/lib/auth-middleware.ts:54-86,110-120`

### Caching

- **Fact:** The Widget Embed has an in-process 60-second cache and explicitly sends `Cache-Control: public, max-age=60`. `rybbit/server/src/api/sites/getEmbedStats.ts:12-15,42-47,98-102`
- **Fact:** The normal overview analytics handler sends its data response without an application-level cache header, while the client analytics query layer defaults to a 60-second React Query `staleTime`. `rybbit/server/src/api/analytics/getOverview.ts:24-35`, `rybbit/client/src/api/analytics/useAnalyticsQuery.ts:117-132`
- **Fact:** Replay list results are cached in the viewer's client for five minutes and replay-detail results for ten minutes; the event log uses a two-second polling interval and zero stale time. `rybbit/client/src/api/analytics/hooks/sessionReplay/useGetSessionReplays.ts:9-21`, `rybbit/client/src/api/analytics/hooks/sessionReplay/useGetSessionReplayEvents.ts:4-16`, `rybbit/client/src/api/analytics/hooks/events/useGetEvents.ts:1-45`
- **Inference:** Revocation stops new API authorization after the config is observed, but it cannot erase data already downloaded into a viewer's browser memory/cache. Rybbit's source does not provide a remote wipe for a previously delivered shared dashboard response.

## Privacy Controls and Audit Contradictions

### Available Controls

- **Fact:** Site settings expose user-ID salting, bot blocking, raw-IP tracking, session replay, URL-parameter tracking, and IP/country/path/hostname/user-agent exclusions. [`Site settings`](https://rybbit.com/docs/site-settings#privacy--security), `rybbit/server/src/db/postgres/schema.ts:75-102`, `rybbit/server/src/api/sites/updateSiteConfig.ts:5-64`
- **Fact:** Raw IP tracking is disabled by default in the schema, but the site setting can enable it and the setting documentation warns that this is not GDPR compliant without a legitimate need and consent. `rybbit/server/src/db/postgres/schema.ts:89-102`, [`Site settings: Track IP Address`](https://rybbit.com/docs/site-settings#track-ip-address)
- **Fact:** URL-parameter tracking is enabled by default, and the site settings documentation tells owners to disable it when sensitive parameters may occur. The public session/event responses include `querystring`. [`Site settings: Track URL Parameters`](https://rybbit.com/docs/site-settings#track-url-parameters), `rybbit/server/src/api/analytics/sessions/getSessions.ts:26-35`, `rybbit/server/src/api/analytics/events/getEvents.ts:14-17,47-58`
- **Fact:** Replay privacy configuration supports masking all inputs, masking selected text, blocking elements, and ignoring input events. [`Web SDK replay privacy`](https://rybbit.com/docs/sdks/web#privacy-config-options)
- **Fact:** User identification supports exact custom IDs and traits such as email/name, and the official documentation warns that it involves personal-data processing and requires a lawful basis, disclosure, access, and deletion capability. [`Identify Users`](https://rybbit.com/docs/identify-users#gdpr--privacy-compliance), [`Identify Users: special traits`](https://rybbit.com/docs/identify-users#special-trait-fields)
- **Inference:** These are collection-time controls, not public-sharing controls. The source has no public/private-link field allowlist, minimum-count threshold, suppression of identified users, IP redaction, replay redaction at read time, export disablement, or share-specific time cap in the public authorization path. `rybbit/server/src/lib/auth-utils.ts:449-480`, `rybbit/server/src/index.ts:212-240,351-425`

## Cimi Implications

- **Fact:** Rybbit has a useful narrow public widget contract, but the Public Analytics/private-link contract is a site-wide read bearer with drill-down, raw event properties, user traits, replay, and GSC paths. The route and response evidence is above.
- **Recommendation:** If Cimi needs public counters or trend cards, model the Rybbit Widget Embed shape: explicit allowlisted aggregates, fixed windows, no individual IDs, no raw URLs/query strings, no traits, no replay, no GSC, and a short cache. This recommendation is based on the narrower official widget contract and source implementation. [`Widget Embeds`](https://rybbit.com/docs/embeds/widget#requirements), `rybbit/server/src/api/sites/getEmbedStats.ts:6-15,52-95`
- **Recommendation:** If Cimi needs private sharing, do not copy Rybbit's single site-wide key without adding per-share records, expiry, rotation/revocation state, request auditing, a data-scope allowlist, and server-side export controls. Rybbit's current model has one key, direct equality, no expiry, no per-viewer identity, and one-minute clustered config staleness. `rybbit/server/src/db/postgres/schema.ts:100-102`, `rybbit/server/src/services/sites/siteConfigurationLifecycle.ts:356-366`, `rybbit/server/src/lib/siteConfig.ts:197-205`, `rybbit/server/src/lib/auth-utils.ts:467-480`
- **Unsafe default to avoid:** Do not make a site public merely to embed a dashboard when the site may collect identified traits, raw IPs, sensitive query parameters, replay content, or owner-connected GSC data. Disable or separately scope those data classes before any public/shared access is enabled. [`Site settings`](https://rybbit.com/docs/site-settings#privacy--security), `rybbit/server/src/index.ts:365-389,430-433,502-509`
