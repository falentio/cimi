## Standards

The aggregate oRPC composition, named dependency objects, `@cimi/utils` reuse, and glossary vocabulary are consistent with the repository conventions. The previous `isRecord` DRY finding is fixed: the shared helper now lives in `packages/utils/src/canonical-json/index.ts`.

### Findings

1. **HARD - sociable test boundary.** `apps/api/src/resources/event-ingestion/testing/service.test.ts:296-314,380-428` mocks `IngestionProtection` and `LifecycleLock`, and `router.test.ts:143-156` mocks `IngestionProtection`. `AGENTS.md` requires sociable tests with repository mocks as the mocked boundary. These tests bypass the real protection and lifecycle adapters instead of exercising the service through repository behavior. Keep repository mocks and use real in-memory protection and lifecycle implementations where the test needs their behavior.

2. **MEDIUM - duplicated duplicate/conflict decision.** `apps/api/src/resources/event-ingestion/service.ts:499-518` keeps separate `existingResult` and `existingBatchResult` implementations for the same fingerprint decision. The two paths can drift. Share the decision and map its result into the singular and batch output types.

3. **LOW - repeated data clump.** `service.ts:499-518` passes `eventId`, `AcceptedEventRecord`, and `fingerprint` through two helpers. `AcceptedEventRecord` names only part of the lookup result, while the same duplicate/conflict input shape remains repeated. Use one result helper input type if the two paths stay separate.

4. **LOW - speculative generality.** `apps/api/src/resources/event-ingestion/index.ts:66-82` exports `combineAcceptanceQuiescence`, but the composition root has one caller at `apps/api/src/index.ts:145`. Keep it private to the composition root or retain the export only if another resource is expected to use it.

5. **LOW - path-string coupling.** `apps/api/src/index.ts:363-367` identifies event-ingestion requests by looking up URL path strings in `EVENT_RAW_REQUEST_LIMITS`. Renaming either procedure can silently remove the raw-body limit. Keep the limit next to the contract route metadata or derive it from the registered procedure definition.

6. **LOW - primitive composite keys.** `coalescer.ts:409-411` and `identity-session.ts:25-27` encode two semantic identifiers as delimiter-joined strings. The encoding is repeated in separate modules and depends on the delimiter remaining outside the identifier grammar. Use a shared key representation or a nested map where the identity is part of the data structure.

### Scope creep

- `apps/api/src/resources/invitation/fixture.ts:9-10,49-60` changes invitation fixture expiry behavior without being part of event ingestion. It makes the fixture date-relative, but it belongs in a separate change.

## Spec

The coalescer's FIFO ordering, all-or-none SQLite append, duplicate/conflict handling, commit wait, and reservation release behavior are implemented and covered. The findings below are outside that core.

### Missing or partial

1. **HIGH - anonymous identity and session continuity are absent.** `identity-session.ts:63-64` returns null Visitor and Session IDs for every anonymous event. When no resolver is supplied, `service.ts:442-446` does the same. The default resolver's only state is an in-process map at `identity-session.ts:44`, and the event contract has no Anonymous Identity field. This prevents the required Visitor and Analytics Session model for anonymous traffic and loses continuity on process restart. The behavior conflicts with `SPECS.md:40,44,71,73` and the Visitor and Anonymous Identity definitions in `CONTEXT.md`.

2. **HIGH - lifecycle admission can race Site deletion.** `service.ts:481-496` bypasses the lifecycle boundary when another ingestion request holds the `ingestion` lease. A second request can resolve an active Site, wait outside the lease, and reserve after deletion begins. The test at `service.test.ts:417-429` explicitly preserves this bypass. This violates the linearization requirement in `SPECS.md:71` and can accept a candidate after the Site has entered deletion.

3. **HIGH - retention cleanup reports work it does not perform.** `retention-cleanup.ts:19-39` ignores the checkpoint data class, deletes only expired `accepted_event` rows through `repository.drizzle.ts:65-79`, and implements `runBackup` by calling `runDerived`. The retention worker then marks all checkpoints for the run completed at `retention-policy/repository.drizzle.ts:327-344`. Derived DuckDB rows and backup retention are not cleaned, but the run reports success. This does not meet the retention cleanup contract for raw, derived, and backup data.

4. **HIGH - session-entry attribution is dropped before analytics storage.** The ingestion path derives UTM, device, browser, OS, and country fields in `attribution.ts:14-27` and stores them on the normalized event. The analytics reader at `packages/db/src/duckdb/index.ts:458-483` does not select those fields, and the session insert at `packages/db/src/duckdb/index.ts:229-254` writes null for every attribution column. Country is also hardcoded to null at `attribution.ts:26`, and the request context has no trusted country source. The stable first-touch attribution requirement in `SPECS.md:44,105` is therefore not observable in analytics.

5. **MEDIUM - identified-user reference validation is not wired in production.** `identity-session.ts:18-23` accepts an optional reference store, but `createEventIngestion` constructs `new DefaultIdentitySessionResolver()` without one at `event-ingestion/index.ts:105-115`. With that default, any non-null `identifiedUserId` passes through `identity-session.ts:66-71`. The direct probe accepted an arbitrary unknown ID. This violates `SPECS.md:73`, which requires unknown IDs to fail validation.

6. **MEDIUM - the `record_excluded` bot result is discarded.** The policy evaluator produces `bot: 'recorded_excluded'` at `collection-policy/evaluator.ts:207-220`, but `NormalizedEvent` has no bot field at `event-ingestion/repository.ts:32-44`, `TAcceptedEvent` has no bot column at `packages/db/src/schema/collection.ts:64-106`, and the append path does not persist the outcome. A configured `record_excluded` policy is therefore indistinguishable from included traffic after admission.

7. **MEDIUM - SPA pageview deduplication is absent.** The event contract accepts a pageview at `packages/contract/src/contract/event-ingestion/schema.ts:67-72`, but the branch contains no route-transition identity or deduplication state. Repeated route notifications can be accepted as separate pageviews. This misses the initial-load, route-transition, reload, and repeated-notification behavior in `SPECS.md:73`.

8. **MEDIUM - ingestion diagnostics are not exposed.** `EventIngestionService` exposes `coalescer.diagnostics` at `service.ts:112-114`, and `HealthSnapshot` has an optional ingestion field at `health.ts:17-25`. However, `systemHealthHandler` returns only the fields in `SHealth` at `health.ts:124-176`, and the public health schema has no ingestion diagnostics field. Queue depth, saturation, failures, WAL growth, and latency cannot be observed through the served health endpoint, despite `SPECS.md:114`.

9. **MEDIUM - rate limits remain code constants.** `protection.ts:4-7,28-33` hardcodes the Site and source-IP rates and bursts. Constructor injection helps tests but no installation configuration supplies these values. `SPECS.md:107` requires numeric thresholds to be installation settings rather than API quotas.

### Implemented but looks wrong

1. **MEDIUM - identity state mutates before durable acceptance.** `service.ts:394-409` resolves identity before `reserve`, while `DefaultIdentitySessionResolver.resolve` creates or updates its in-memory session at `identity-session.ts:72-108`. A queue saturation, reservation failure, or failed flush can leave session state for an Event that was never accepted. A retry can then reuse the state even though no corresponding acceptance exists. The acceptance boundary in `SPECS.md:71` and the no-side-effect rule in `SPECS.md:139` need a transactional or deferred identity update.

## Follow-up Remediation

### Fixed

- Sociable event-ingestion tests now use real in-memory protection and lifecycle adapters; repository doubles remain the mocked boundary.
- Duplicate/conflict output mapping and composite reservation/session keys are shared or structurally represented; raw request limits derive their keys from contract route metadata.
- Anonymous identity/session assignments are staged until durable acceptance and can recover stored attribution/session state; configured Identified User references are validated against active Site profiles.
- Site deletion admission is serialized with the shared lifecycle boundary.
- Retention now handles identity cleanup, analytics rebuild/deletion, replay material, raw acceptance data, and historical backup cleanup in the required order.
- Event attribution, country context, bot outcomes, pageview deduplication, diagnostics, and configurable protection thresholds are persisted or wired through their production boundaries.
- Backup restore reapplies redactions, tombstones, and current non-active Site lifecycle state. Restore cleanup is wired by default, and abandoned cleanup claims can be reclaimed after their lease expires.

### Open

- The contract still permits an omitted `anonymousIdentityId`; those events have no durable anonymous identity or cross-request continuity. A server-issued identity transport is still needed if the specification requires continuity without a client-provided identifier.
- `apps/api/src/resources/invitation/fixture.ts` remains unrelated scope change from the original branch and should be separated or explicitly retained.
