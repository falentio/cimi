# Reporting audit findings

This audit covers PR #68 at commit `2434308` for issue #45. The issue owns the
traffic-report and event-report query behavior over the DuckDB projection.

## Findings to fix in issue #45

### F1. Event filters ignore the selected event kind

Status: fixed.

`SEventReportFilter` validates fields without the request's `eventKind`, and
`EventReportService.compileFilters` does not pass `eventKind` to the compiler.
An incompatible specialized field can therefore return an empty report instead
of `BAD_REQUEST`.

Evidence:

- `packages/contract/src/contract/event-report/schema.ts:54-104`
- `apps/api/src/resources/event-report/service.ts:199-209`
- `docs/specs/analytics-reporting/event-report/SPECS.md:116`
- `docs/specs/ACCEPTANCE.md:443-457`

Fix the validation at the report boundary and add a regression test for each
specialized field family that the selected kind does not support.

### F2. Null is accepted for `not_equals`

Status: fixed.

The event contract and compiler accept `null` for both `equals` and
`not_equals`. The SQL adapter renders the latter as `IS NOT NULL`. The contract
allows explicit null only for `equals` against a nullable field selected by the
event kind.

Evidence:

- `packages/contract/src/contract/event-report/schema.ts:54-80`
- `packages/kernel/src/reporting/query/compile-filter.ts:182-197`
- `packages/db/src/duckdb/reporting-query.ts:1000-1010`
- `docs/specs/ACCEPTANCE.md:451-457`

Reject null for `not_equals`, ordering, and `contains` operators.

### F3. Negated presence filters can match rows without an actor

Status: fixed.

`has_not_done` uses `NOT EXISTS` with equality against nullable visitor or
session IDs. A row with a null actor ID has no possible matching presence row,
so the negated predicate returns true.

Evidence:

- `packages/db/src/duckdb/schema.ts:33-65`
- `packages/db/src/duckdb/reporting-query.ts:934-968`

Define the null-actor behavior at the query boundary and cover it with a
reporting query regression test. The fix must not change positive presence
matching.

### F4. Traffic breakdown Fact-Work undercounts distinct operations

Status: fixed.

Traffic breakdown admission declares two distinct-count operations. The query
executes a distinct Session denominator, a distinct dimension count, and a
distinct Session count for grouped rows.

Evidence:

- `apps/api/src/resources/traffic-report/service.ts:40-47`
- `packages/db/src/duckdb/reporting-query.ts:451-518`
- `packages/kernel/src/reporting/fact-work.ts:27-35`
- `docs/specs/analytics-reporting/METRICS.md:30-32`

Make the declared work match the SQL that the breakdown executes and preserve
the fixed admission budget.

## Findings outside this PR's implementation scope

### F5. Approved profile filters have no projection support

The collection-policy gate recognizes approved trait keys, but the DuckDB
projection has no profile trait dimension. The adapter returns `BAD_REQUEST`.
The PR documents this deferral. Projection work belongs to the collection and
identity work tracked under #34, #42, and #43.

Evidence:

- `packages/db/src/duckdb/reporting-query.ts:818-822`
- `docs/specs/README.md:70`
- PR #68 audit response

### F6. Exit page and coarse geography are not populated

The projection has no exit-page column, and rebuild writes `region` and `city`
as null. The PR documents the empty breakdown behavior. Populating these
dimensions requires projection changes outside the report query implementation.

Evidence:

- `packages/db/src/duckdb/reporting-query.ts:128-134`
- `packages/db/src/duckdb/index.ts:375-400`
- `docs/specs/analytics-reporting/traffic-report/SPECS.md:56-58`

### F7. Site deletion can race an analytics read

Site scope and analytics readiness are checked before the query, but no site
lifecycle lease spans admission through execution. Cross-resource lifecycle
integration belongs to #52, which issue #45 explicitly leaves out.

Evidence:

- `packages/guard/src/site.ts:27-51`
- `apps/api/src/resources/traffic-report/service.ts:63-66`
- `apps/api/src/resources/event-report/service.ts:165-168`
- `github.com/falentio/cimi/issues/52`
